# Production Quality Gate

«Готово» = код + контент + реальный запуск + gameplay smoke + **real UI clickthrough** + полноразмерный visual review + **количественный Game Quality Scorecard** + исправления + merge.

Для любой заметной игровой/сюжетной/UI/арт итерации обязателен `docs/03-production/PLAYTEST_RUBRIC.md`.

## Game Quality Score Gate — обязательный

До merge необходимо заполнить все 8 блоков `PLAYTEST_RUBRIC.md`:

1. Character Presence;
2. Art Quality;
3. UI/UX;
4. Narrative Logic;
5. Interest & Pacing;
6. Gameplay Value;
7. Tone & Atmosphere;
8. Secondary Characters.

Merge запрещён, если:

- есть хотя бы один `HARD FAIL`;
- общий score ниже **32/40**;
- хотя бы один блок ниже **3.5/5**;
- `Character Presence < 4/5`;
- для visual/art pass `Art Quality < 4/5`;
- для UI/gameplay pass `UI/UX < 4/5`;
- `Interest & Pacing < 3.5/5`;
- reviewer не ответил `YES` на вопрос «Would I voluntarily play the next 10 minutes?»;
- scorecard не содержит минимум 3 конкретных слабых места build;
- visual review основан только на contact sheet, а полноразмерные critical screenshots не открывались отдельно.

`3/5` = рабочий прототип, **не production PASS**.

Хороший средний score не может компенсировать hard fail персонажа, арта, UX, логики или gameplay.

## Canon gate

- [ ] Изменения не противоречат `docs/CANON.md`.
- [ ] Катерина соответствует `web/assets/katerina.webp`.
- [ ] Каре Катерины сохранено.
- [ ] Катерина **фактически видима на screenshot** обязательных key scenes, а не только существует в DOM.
- [ ] Кощей — чёрный кот с зелёными глазами; до reveal не ведёт себя как говорящий персонаж.
- [ ] Кощей визуально не выглядит случайным mascot/placeholder.
- [ ] Новые факты либо каноничны, либо явно помечены как рабочие.

## Functional gate

- [ ] `npm test` проходит.
- [ ] `npm run validate` проходит.
- [ ] `npm run agent-smoke` проходит.
- [ ] `npm run ui-playtest` проходит через реальные DOM-clicks/Chromium hit-testing.
- [ ] Изменённый flow реально пройден от начала до конца.
- [ ] Нет console/page errors в browser smoke.
- [ ] Нет тупиков обязательного пути.

## Agent gate

- [ ] `observe()` возвращает состояние без авторских spoilers.
- [ ] `actions()` перечисляет реальные доступные действия.
- [ ] `act()` использует то же состояние и правила, что UI.
- [ ] Есть полный agent playthrough до завершения slice.

## UI/UX gate

- [ ] При первом использовании важная система не спрятана в маленькой icon-only кнопке.
- [ ] Обязательный click target не меньше `44×44 px`.
- [ ] Телефон имеет заметный first-use affordance и usable body не уже `360 px` на desktop.
- [ ] Reasoning workspace/board занимает минимум `70%` доступной площади игрового viewport в активном режиме.
- [ ] На 1366×768 все обязательные choices и CTA видимы и кликабельны.
- [ ] На экране за 5 секунд понятно, что сейчас важно и что можно сделать.
- [ ] Board/workspace connectors приходят в реальные anchors с погрешностью не более `8 px` на 1920×1080 и 1366×768.
- [ ] Connector lines не проходят через нерелевантные карточки и не создают ложных связей.
- [ ] UI ощущается частью VN, а не generic dashboard/web app.

## Visual gate

Для заметной UI/арт-задачи:

- [ ] Игра реально отрендерена.
- [ ] Сделаны screenshots ключевых экранов.
- [ ] Каждый critical screenshot открыт отдельно в полном размере.
- [ ] Contact sheet использован только как навигация, не как единственное evidence.
- [ ] Проверены 1920×1080 и 1366×768.
- [ ] Первый экран содержит художественный фон и крупную Катерину.
- [ ] За 5 секунд на menu понятны protagonist, жанр и CTA.
- [ ] Нет налезаний, обрезанного текста и случайных артефактов.
- [ ] Production art не выглядит размытым/размазанным/пикселизированным.
- [ ] Full-screen raster background имеет достаточное native resolution; целевой baseline — минимум 1920×1080.
- [ ] CSS blur/filter не используется для маскировки низкого качества source asset.
- [ ] Диалог/choices читаются без разрушения композиции.
- [ ] Персонажи согласованы по стилю, масштабу и свету.

## Art gate

Перед добавлением production art:

- [ ] открыть source asset в реальном размере;
- [ ] записать native dimensions;
- [ ] проверить sharpness на 100%;
- [ ] проверить лицо, руки, анатомию, одежду, татуировки, аксессуары;
- [ ] проверить отсутствие случайного текста/иконок/UI внутри изображения;
- [ ] проверить locked character reference;
- [ ] проверить края cutout/alpha;
- [ ] проверить арт внутри реальной сцены;
- [ ] generated poster/contact sheet/mокап не используется как production asset.

Если арт не проходит gate, он не становится каноном только потому, что уже был сгенерирован.

## Character Presence gate

- [ ] Катерина крупно и реально видима на menu/key art.
- [ ] Катерина присутствует в обязательных character/emotional scenes текущего slice.
- [ ] Sprite не исчезает из-за opacity, mask, stacking, alpha или crop.
- [ ] Emotion/staging Катерины соответствует сцене.
- [ ] Ключевой screenshot не выглядит как background + UI без главной героини.

## Narrative Logic gate

- [ ] Для каждого крупного действия понятно, почему персонаж делает это именно сейчас.
- [ ] Катерина не получает внезапную компетенцию полицейского/криминалиста/мага.
- [ ] Катерина не рискует без показанной личной причины.
- [ ] Персонажи знают только то, что могли узнать к текущему моменту.
- [ ] Каждый крупный переход можно объяснить через `причина → решение → действие → последствие`.
- [ ] Опасность вызывает человеческую реакцию, а не превращает Катерину в action hero.
- [ ] Сценарий не использует «так надо следующей сцене» как мотивацию персонажа.

## Interest & Pacing gate

- [ ] У каждой сцены есть драматическая функция, а не только переход к следующей кнопке.
- [ ] Есть как минимум один настоящий спокойный character beat до/между крупными reveal.
- [ ] Крупные reveal не идут пулемётной очередью без реакции Катерины.
- [ ] Choices меняют тон, отношение, сохранённую деталь или будущий контекст.
- [ ] Mystery reveal отвечает на маленький вопрос и создаёт более точный новый вопрос.
- [ ] Reviewer может назвать момент, где впервые стало реально интересно.
- [ ] Reviewer может назвать самый скучный/слабый beat.
- [ ] Финал создаёт конкретный hook, ради которого хочется продолжить.
- [ ] Ответ на «Would I voluntarily play the next 10 minutes?» — `YES`.

## Gameplay gate

- [ ] В сцене есть понятная цель игрока.
- [ ] Игрок делает осмысленное действие, а не только читает.
- [ ] В vertical slice есть минимум 3 разных типа player action.
- [ ] Нет трёх и более последовательных «Продолжить/Идти дальше» без meaningful interaction.
- [ ] Choices звучат как Катерина.
- [ ] Choices не являются тремя перефразировками одной реакции.
- [ ] Альтернативное действие меняет хотя бы локальный state/context/reaction.
- [ ] Будущие детективные выводы подготавливаются фактами.
- [ ] Магия не выдаёт абсолютную истину.
- [ ] Романтический beat не ломает субъектность Катерины.
- [ ] Есть причина перейти к следующей сцене.

## Secondary Characters gate

- [ ] Кощей визуально соответствует общей игре и не выглядит дешёвым mascot.
- [ ] Reveal говорящего Кощея не превращается в непреднамеренную комедию.
- [ ] Егор визуально принадлежит тому же миру и не выглядит карикатурным «Дракулой».
- [ ] Егор/Кощей не существуют только как lore dispensers.
- [ ] Реакции на choices различимы.

## Evidence gate

В PR должны быть зафиксированы:

- [ ] exact commit SHA;
- [ ] реальные UI playthrough routes/viewports;
- [ ] список critical screenshots;
- [ ] полный 8-block scorecard;
- [ ] `Hard fails: NONE` или конкретный список;
- [ ] strongest evidence и weakest point для каждого блока;
- [ ] минимум 3 слабых места build;
- [ ] fixes, сделанные после первого review;
- [ ] итог `ACCEPT / REWORK / REJECT`.

Нельзя ставить `4` или `5` без конкретного evidence.

## Git gate

- [ ] Branch основан на актуальном `main`.
- [ ] В diff нет временных test/upload файлов.
- [ ] PR содержит фактические результаты tests, real UI playtest, scorecard и visual review.
- [ ] PR mergeable.
- [ ] После merge проверено, что итог находится в `main`.
- [ ] Post-merge push CI на `main` зелёный.
