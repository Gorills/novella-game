# Production character assets

## Катерина — locked

`katerina.webp` — прямой production asset из пользовательского locked visual reference.

Канон: лицо, пропорции, татуировки и **обязательное тёмно-красное каре** нельзя переосмысливать без прямого решения пользователя.

## Егор — locked v1

`egor.webp` больше не provisional: это **locked face / color / silhouette reference v1** для Егора в текущем vertical slice.

Зафиксировано:

- очень светлая кожа;
- холодные голубые глаза;
- тёмные слегка небрежные волосы;
- стройное телосложение;
- угловатое лицо без модельной глянцевости;
- спокойная, сдержанная, потенциально опасная подача;
- современная тёмная одежда без театральной «вампирской» стилизации.

Любые будущие эмоции, full-body, CG и альтернативные ракурсы Егора обязаны сохранять лицо, возраст, пропорции, цвет глаз/кожи/волос и общий силуэт из `egor.webp`. Если новая генерация лишь «похожа», но меняет человека — она не принимается.

Полный multi-view character sheet можно расширить позже, но он должен **выводиться из этого locked v1**, а не заново придумывать персонажа.

## Binary asset discipline

Binary art не проталкивается в production через случайные временные base64/chunk-workflows только потому, что текущий connector не умеет безопасно писать binary напрямую. Для новых крупных visual assets нужен штатный Git/Git LFS или отдельный подготовленный asset PR с checksum-валидацией.

Неудачная доставка asset не является поводом подменить его случайной новой генерацией или CSS-заглушкой и объявить работу завершённой.

## Packed fallback

`packed/katerina/` остаётся legacy transport-safe fallback для канонического референса Катерины. Нормальные бинарные `katerina.webp` / `egor.webp` имеют приоритет, если уже закоммичены.

`tools/materialize_packed_assets.py` не должен перерисовывать или перекодировать уже существующий locked asset.
